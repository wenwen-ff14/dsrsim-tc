# 絕龍詩 P2 聖仗練習

目前版本為 `0.4.0.60`。場地沿用天候 45，對應 `obset_r1fz_bg_04` 的 `r1fz_d00_stg_01`。

NPC 第一輪選塔依 [Tuuf 聖仗隕石規則](https://ffxiv.tuufless.com/elemental/dsr/02_thordan/#part-2-meteors)：隕石職能取外塔，優先中間、逆時針、順時針；南北只在預設分配形成雙人同側的 120°／240° 困難配置時嘗試調整，不再為湊成 180° 而放棄正常的 150°／210° 配置。無法避免的困難配置仍保留。非隕石職能取同區剩餘外塔，沒有外塔則取順時針內塔或補空塔。

第一輪塔出現後，NPC 先往自己分配的塔方向走 2.5 碼示意，33.5 秒回兩人集合點，冰圈結算後再正式走去踩塔。示意時間為模擬器的溝通安排，並非 logs 中的強制機制事件。實際隕石路線仍依兩座起點塔計算，玩家指定跑動角度功能保留。

0.4.0.23 依 FFLogs 第 42 場重新校正施法、快照與隕石落地，來源、時間換算及仍為近似的部分見 [校正紀錄](DSR-P2-reference.md)。
已移除「複製騎士動作診斷」按鈕及每輪定時診斷收集。
已從繁中遊戲資料核對場中 `(100,0,100)` 的金色平台模型 `r1fz_d0_grd01`；
前兩版天候 44／2 分別選到了綠色場地及教堂相關場景，原先說明的 P2 映射有誤。
環境在場景載入完成後套用並持續核對，不再只等待固定一秒寫入。

托爾丹開場在中央讀條，補入原生瞬移／再出現動作，聖仗及龍眼技能以自身為演出目標，參照

（ActionTimeline 34，`battle/idle`）；施法與移動時交還動畫控制。
這是針對雙手張開及缺劍的初始化修正，尚未在繁中遊戲內確認實際姿勢。
托爾丹開場至上天前、以及機制結束回場後可選取為攻擊目標；機制期間不可選取。

標點採用 [Tuuf P2 內圈座標](https://ffxiv.tuufless.com/elemental/dsr/#markers-1)，半徑約 13 公尺。

音量依遊戲的背景音樂／音效設定，不修改全域音量。
白球爆炸前保留一秒原技能讀條，AOE 由技能原生 Omen 提供，移除額外的通用圓圈；沒有原生 Omen 的技能不額外補圈。

開場八名騎士於 9.2 秒隨托爾丹一起起飛，10.6 秒收起。澤菲蘭、阿代爾斐爾與讓勒努保留原物件，11.5 秒回場時等待三者模型與武器姿態全部準備好，再同時播放落地動作。衝鋒移除原本 0.6 秒的動作鎖，移動速度由 50 調至 100（相同距離耗時縮短一半），三段衝鋒皆適用。衝鋒開始及傷害時點沿用既有時間軸；演出速度為試調值，仍需實機驗證。

P2 落地演出維持 32 幀，結束後雙劍盾騎士試播 B 組起手 `132` 接循環 `133`，黑騎試播 A 組起手 `130` 接循環 `131`；其他角色維持戰鬥待機 `34`。開場與再次落地皆使用此設定，施法、移動與起飛仍接管動畫。起手銜接由原生 PlayActionTimeline 的 intro／loop 參數處理；外觀與持續動作是否符合實戰需實機確認。

衝鋒後九組白球的原生 AOE 提示與傷害判定在上一版基礎上再提前 0.15 秒：第一組於 20.75 秒提示、21.75 秒判定，最後一組於 26.35 秒提示、27.35 秒判定。保留一秒預警及各組 0.7 秒間隔，NPC 仍依實際爆炸數移動。這項提前量為試調值，非新的 logs 校正結果；第一組提示必須晚於 20.709 秒的白球生成。

一、二刀標記等待三名騎士的落地動畫全部結束後才顯示，且只顯示一次；仍於約 27 秒到期。模型載入延遲也會延後標記。

本機技能 25571 的釋放時間軸為 `mon_sp/d1054/mon_sp020`，內含 `SE_Vfx_Monster_d1054_sp20_c.scd` 與 `SE_Vfx_Monster_d1054_sp20_t.scd` 兩段音效引用。施法與退場前現在明確釋放自訂待機所占用的基礎動畫槽，以排除待機循環干擾；尚未確認這就是缺音原因，也尚未實機驗證音效恢復。
冰圈落下後保留 2.5 秒離場緩衝，過後停留／踏入仍會判定；火圈判定獨立保留。
冰火殘留圈改用從繁中遊戲場景資源核對的原生地面特效，不再以通用 AOE 提示圈替代。
套用原始 SGB 的冰圈 1.3 倍、火圈 1.4 倍縮放，補上上一版遺漏的大小；傷害判定半徑仍為七公尺。
緩衝秒數屬練習校正值，尚未以繁中實戰紀錄確認伺服器傷害跳點。
這些原生模型與場地變更仍需繁中客戶端實測；流程驗證不能取代遊戲內畫面確認。
更新前先「離開模擬」回到旅館，再停用舊 DLL、重新載入。
順時針時東側白騎士朝南、西側朝北；逆時針則相反。暗騎士與外圈托爾丹朝場中。

修正玩家正常跑隕石仍被判定太近的情況：玩家被點名時，另一名隕石 AI 會配合玩家跑圈進度，

## 操作

將 `AnoMech/bin/x64/Release/AnoMech.dll` 加入 Dalamud 的 Dev Plugins 並載入。
若之前載入舊 DLL，先停用舊項目，更新同一路徑後再啟用。
在旅館房間輸入 `/ano`，選擇職責後「開始」。
「重置」清除本輪並保留模擬場地；「離開模擬」返回旅館。

「無敵練習」保留失誤訊息，可用於先熟悉整段流程。
「成功後自動重開」用於連續練習，死亡會取消。
關閉站位提示後仍可保留戰術圖；完全不看圖則取消「顯示戰術圖」。
戰術圖的北方固定向上，綠色箭頭表示玩家位置與面向。
塔出現後才顯示黃圈，紅圈為火圈或白球危險區，藍圈為冰圈。

固定種子、騎士方向與隕石點名設定在下一輪生效。
「自己隕石跑動角度」可選隨機／120°／150°／180°／210°／240°，下次開始生效。
指定角度會保證點名玩家，並以玩家順時針跑向另一座起點塔的角度篩選合法配置；另一名點名者跑剩餘角度。
指定角度時，隕石點名職能選項暫停使用；切回隨機角度會恢復原本點名偏好。
「保證點名自己」適合反覆練習跑隕石；隕石配對仍限制為兩名坦補或兩名輸出。
外圈成員需自行開防擊退，跑隕石的長路線需使用疾跑。
「模擬自身技能效果」必須開啟，親疏自行與沉穩詠唱才會在模擬中授予六秒防擊退。

## 實作與驗證範圍

保留 Dalamud API 13、.NET 9、C# 13，以及只能從旅館開始的限制。
原有關卡仍在 `Game` 的目錄中，以型別篩選暫時隱藏，未刪除原始碼。
主視窗、一般設定、關卡設定與主要失誤訊息已繁中化；開發者除錯面板仍保留部分英文欄位。

機制編號與幾何參考 [BossMod DSW2](https://github.com/awgil/ffxiv_bossmod/tree/master/BossMod.Ultimate/Endwalker/Ultimate/DSW2)。
事件採約一分鐘的練習時間軸。細部爆炸／隕石快照間隔、跳躍距離門檻，以及火圈中心距離
仍屬練習模型近似值，不能視為逐幀戰鬥紀錄重播。火圈半徑為七公尺，中心暫設距場中十二公尺。
地面塔使用通用範圍特效，冰火殘留圈使用原生地面特效，並提供戰術圖輔助；龍眼場景效果、原生動作與地圖外觀待繁中客戶端確認。
尚未模擬 HP／減傷計算、隕石距離衰減傷害及完整 P2。

離線驗證工具直接引用本關卡的事件、隨機狀態與 AI 原始碼，使用簡化角色移動替身：

dotnet run --project tools/DsrValidation/DsrValidation.csproj -c Release

漏塔／視線／隕石重疊失誤判定、冰圈緩衝前離開及緩衝後停留，以及 AI 不移動玩家。
另檢查 15 組玩家以正常速度跑半圈、AI 同伴配合移動的隕石路線。
同時檢查托爾丹可選取時段與隕石頭標出現時機。
以保存的 FFLogs 時間樣本比對 24 組施法、龍眼與七次隕石落地，涵蓋 30／60／144 FPS。
指定 120°／150°／180°／210°／240° 各一百組，合計五百組完整路線；八職責各五種角度共四千組配置亦納入檢查。
替身不執行遊戲碰撞、動畫鎖、原生特效或封包，通過不代表遊戲內已驗證。

另窮舉 810 種合法外塔配置，驗證選塔優先序、只調整可避開的同側困難配置，並檢查即使能配成 180° 也保留原本 150°／210° 優先序的回歸案例。

實機請確認：選單中文字、七名隊友生成、劍與隕石點名、塔顯示、
防擊退、死亡提示、連續重置及離開後角色恢復。
若出現站位或時序問題，提供畫面的種子、職責與秒數即可重現同一組機制。
